## The pre-registered rule, applied

Written down before the number was visible, in the check-in that read it:

> - paired lower bound **ABOVE 0**: measurable gain, step 4 deletes
>   `battleground`.
> - lower bound **AT OR BELOW 0**: not a measurable gain. Do **NOT** delete
>   `battleground`.

The lower bound is **-0.001**. That is at or below zero, by one thousandth.

**So `battleground` stays, and step 4 does not happen.** Not because one
thousandth is meaningful -- it is not -- but because a decision rule that
moves after the number arrives is not a decision rule, and this project's
last two weeks are a record of what happens when inference gets ahead of
measurement (see
[the retraction](2026-09-21-the-leak-cost-nothing.md)). The line was drawn
at zero in advance. It reads -0.001.

## What IS established, and it is not nothing

**With the fit on, the bot beats the strongest anchor.** `fit-bc-on` reads
0.530 [0.513, 0.547] against `bc5ef93`: its own interval clears 0.500, on
the full 1024 seeds, with no missing shard. **That is the first
configuration measured to beat `bc5ef93`, where the shipped bot only draws
it (0.502.)** It is a weaker statistic than the paired difference -- a
level, not a comparison -- so it does not substitute for the rule above.
But it is a clean reading and it points the same way.

Both seats gain against the base arm (US 0.575 -> 0.581, USSR
0.449 -> 0.479), and the USSR gains more, the same pattern the
`07d553a` run showed.

## The determinism check, which passed

The falsifiable prediction, written before this dispatch: **`fit-bc-on`
should reproduce exactly 0.530 [0.513, 0.547]**, because the first
dispatch's 15-of-16 pooling read that and a benchmark game is a pure
function of its inputs. If it did not, determinism was broken and the
shard-cache design was invalid.

It reproduced **0.530 [0.513, 0.547]**, and the paired difference
reproduced **+0.023 [-0.001, +0.047]** on the same 896 seeds. Bit for bit,
two independent dispatches, two days of runner time apart.

**That is the shard cache's warrant, demonstrated rather than argued** --
and it is also the whole yield of this dispatch. About eleven runner-hours
bought a confirmation that the numbers were already right, because the one
shard that would have changed the answer failed the same way twice. Had
`scripts/arm_identity.py` existed when this ran, the re-dispatch would have
been one shard.

## Why the answer is still 896 seeds

`fit-bc-base [5/8]` -- seeds 64640-64767 -- ran 1h51m on the first dispatch
and hit the 180-minute job ceiling on this one. Same arm, same shard index,
therefore the same 128 seeds; shards are deterministic, so this is a
reproducible slow slice. The mechanism and the proposal for the wall-clock
cap that would at least let it report a partial are in
[the cheaper-readings note](2026-09-21-cheaper-readings.md).

The practical consequence: **this block cannot produce a 1024-seed paired
reading** until that slice is either fixed or understood. A third dispatch
of the same arms on the same block would return +0.023 [-0.001, +0.047]
again, exactly, and that is now a measured fact rather than a prediction.

## What this selects

The plan's branch is the refit, and the plan already named the suspect:

> `source_revision` is `598e4d1`, so the weights were fitted on self-play
> positions from a bot **two structural changes ago** -- before the region
> margin was deleted and before `vp_swing` 3.0. Weights fitted on the
> positions one bot reaches need not price the positions another reaches.

That reasoning is stronger now, not weaker. The fit is worth **+0.023** on
a bot two structural changes newer than the positions it was fitted to, and
it is one thousandth short of measurable at 896 seeds. A refit at current
main is the change most likely to move it clear.

Two dispatches are worth doing and neither should be confused with the
other:

1. **The refit**, then `fit-{base,on}` again. This is the plan's branch and
   the one that could make step 4 happen.
2. **The same arms on a FRESH block**, which sidesteps the broken slice and
   gives an independent 1024-seed paired reading of the weights as they
   stand. Cheaper, and it answers "is -0.001 the block or the weights?"
   -- a question the same block can no longer answer however many times it
   is run.

Neither is dispatched. Both are the maintainer's call.
